How pairing works

User signs in with Supabase, phone puts the box on Wi‑Fi over Bluetooth, then binds it to that account through aios-cloud. 

sequenceDiagram
  participant Phone
  participant Supabase
  participant Device as AIOS Box
  participant Cloud as aios cloud

  note over Phone,Supabase: 1 Sign in
  Phone->>Supabase: Authenticate user
  Supabase-->>Phone: Session JWT

  note over Phone,Device: 2 Get the box online over Bluetooth
  Device-->>Phone: Advertise BLE and WiFi list
  Phone->>Device: Encrypted SSID and password
  Device->>Device: Join WiFi
  Device-->>Phone: LAN IP and provisioning key

  note over Phone,Cloud: 3 Bind the box to the user account
  Phone->>Cloud: Request pairing code with JWT
  Cloud-->>Phone: pairing_code
  Phone->>Device: Send pairing code to box
  Device->>Cloud: Redeem code
  Cloud-->>Device: device token and tunnel
  Device-->>Phone: local_token

  note over Phone,Cloud: 4 Everyday use
  Phone->>Device: API calls with local_token
  Device->>Cloud: Relay and public tunnel

Supabase auth happens first so aios-cloud knows which user owns the pairing code. Bluetooth never carries account tokens — only Wi‑Fi credentials. Unpair drops the account link; factory-reset also wipes the provisioning key.
